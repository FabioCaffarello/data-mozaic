# BC04 durable coordination contract drafts

`PublicationGrant.schema.json` is a draft BC04-owned cross-context contract. It authorizes BC05 to publish exactly one tenant, run, attempt generation, sealed OutputSet and manifest. Its signed payload uses RFC 8785 JSON Canonicalization Scheme over every property except `signature`; the `Ed25519` signature is unpadded base64url with the `ed25519:` prefix. `key_id` selects a configured BC05 public verification key. BC05 receives no signing key and cannot mint BC04 grants from the verifier configuration.

BC04 retains the Ed25519 private seed; BC05 stores only the matching public key. The worker receives neither. This is a narrow service-boundary signature, not a general identity system or BC11 production authorization. Local fixture composition may load both sides in one trusted operator process; production deployment must keep private-key material out of BC05.

Grant validity is the durable PostgreSQL reservation state. Draft v1 has no time-based expiry because BC04 cannot revoke a grant after BC05 may have begun publication. The reservation blocks attempt replacement until BC05's matching durable receipt is recorded. Consequently, MongoDB unavailability can leave a Run in `finalization_pending`; bounded reconciliation restores liveness when BC05 becomes available. Key rotation uses a new key ID for new grants and retains prior public keys until all reservations signed by them have a resolved receipt or are otherwise conclusively reconciled. Removing an old verifier key must not strand an unresolved reservation.
