# Contratos BC14 v1.0.0 — draft

Schemas JSON Schema Draft 2020-12, owner BC14; consumidores planejados: solicitante autorizado para ScoutRequest e BC15/revisores para achados, manifesto e proposta. Nenhum contrato foi homologado ou implantado. Exemplos [válidos](fixtures/valid) e [inválidos](fixtures/invalid) são ilustrativos e não contêm dados reais. Cada propriedade tem sua semântica no `description` do schema; objetos são fechados e campos declarados são obrigatórios. IDs são opacos e escopados por tenant na aplicação; escopo, identidade e autorização não são validados pelo schema. Os IDs `$id` são identificadores, não endpoints disponíveis.

Datas usam RFC 3339 UTC com sufixo `Z`; strings não vazias, enumerações fechadas e limites são restrições estruturais. Manifesto contém referências, não bytes nem política de acesso. `sha256` descreve os bytes referidos, não a identidade de observação. Um finding exige evidência mas sua pertinência, verificação independente e suficiência são semânticas externas. Proposta não é playbook executável nem aprovação. IDs referenciados devem pertencer à mesma sessão, source e tenant e ser acessíveis; isto exige validação de aplicação e BC06. O conteúdo é sanitizado e não deve conter credenciais, tokens ou dados sensíveis indevidos.

A versão literal `1.0.0` identifica este draft, não estabilidade de produção. Campos desconhecidos e enums desconhecidos são rejeitados: adição é incompatível para esses consumidores e exige major ou negociação explícita; nenhum minor é automaticamente compatível. Para evoluir, conservar versão anterior, testar consumidores e acordar migração/depreciação. Nenhuma compatibilidade de linguagem é comprovada até executar consumidores reais; JSON e fixtures são a base comum. `make test` verifica metaschemas, exemplos e mutações negativas, além do fluxo S1 com fakes de autorização, referências e integridade dos bytes da fixture. Não comprova retenção, segurança de rede ou garantias de serviços reais.
