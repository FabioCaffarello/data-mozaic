# ADR 008 — Estado durável, command receipts e outbox Scout

- Status: Proposed; implementation experiment exists, not homologated.
- Contexto: S1.1 fake repository is process-local. S1.2 needs restart recovery and cross-process optimistic concurrency without moving BC14 rules into infrastructure.
- Decision proposal: use PostgreSQL with psycopg 3 and explicit SQL migrations. Persist versioned structured JSON documents (never pickle), command receipts, and BC15 outbox rows. Use PostgreSQL `READ COMMITTED`; each local create/save transaction writes the session CAS update, receipt snapshot/status, and proposal outbox event atomically. CAS uses `UPDATE ... WHERE session_id = ? AND version = ?` and requires a returned row. Stable command/effect IDs make caller retries idempotent. BC06 bytes and BC15 decisions remain owned by those contexts.
- Alternatives: SQLAlchemy Core/Alembic; ad-hoc schema bootstrap; distributed transaction with BC06/BC15. Explicit SQL is smaller for this initial schema and makes constraints/transaction boundaries visible; an established migration framework should be reconsidered if migration complexity grows. Distributed transaction is rejected as cross-context coupling and is not implemented.
- Aggregate document: `ScoutSession` identity, optimistic version, state, exact `SourceRef` revision, principal, requested/effective scope, budget, observation/manifest/finding/proposal references and handoff outcome. Document version is explicit and unsupported versions fail closed. Domain invariants remain in `domain/` and must be rechecked on commands.
- `CommandReceipt`: principal + idempotency key scope, stable command ID, command kind, canonical request/fixture fingerprint, session FK, `in_progress|uncertain|completed`, response snapshot and timestamps. Authorization is checked before returning a prior result. Same fingerprint resumes/returns; different fingerprint conflicts.
- `OutboxEvent` / handoff intent: stable event and proposal IDs, aggregate/version, event kind, BC15 channel, contract projection, `pending|sent|uncertain`, attempt count, next-attempt timestamp, transport receipt and separately stored BC15 business receipt. `sent` means transport confirmation only; `business_ack` means BC15 received it. Neither implies approval or BotRelease.
- Custody boundary: BC06 owns bytes, integrity, access and retention. BC14 persists only stable custody intent, evidence reference and digest returned by custody. An ambiguous external write is marked unknown and must be queried/retried by stable identity and verified before an EvidenceManifest can be sealed. The integration test uses a separate test-owned object table; no productive BC06 service/client is implemented.
- Crash timeline: (1) before DB commit, transaction rollback leaves no aggregate/receipt/outbox; (2) after commit and before relay, pending outbox survives restart; (3) after remote execution and before local confirmation, mark/recover as uncertain and query/retry the stable ID; never infer success from timeout; (4) restart scans pending/uncertain outbox and resumes only after fresh authorization and exact source revision check; (5) concurrent processes compete through version CAS and only one update succeeds.
- Consequences: PostgreSQL is a runtime dependency only for the durable adapter and its integration profile; offline demo remains fake-backed. Outbox gives durable intent and at-least-once relay potential, not exactly-once delivery. Receiver deduplication and authorization freshness contracts remain required.
- Risks / open gates: the adapter was exercised against PostgreSQL 18.4 locally. Database transaction crash boundaries and a test-only BC15 receipt simulation pass, but full application process restart recovery, outbox leasing/backoff, BC06 uncertain-write recovery, receipt retention, schema upgrade policy and multi-tenant authorization need integration/security review. No ADR is Accepted without human review.
- Validation: tests cover receipt persistence across repository instances, fingerprint conflict, two-connection CAS, rollback including outbox, migration repeat/checksum, process exit before/after commit, and test-only BC15 dedup after lost ACK. Domain import tests exclude psycopg/Postgres. BC06 recovery remains unimplemented.
