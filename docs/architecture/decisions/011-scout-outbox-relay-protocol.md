# ADR 011 — Scout outbox relay lease and fencing protocol

- Status: Proposed; local implementation experiment only.
- Context: the BC14 proposal outbox was durable, but `RunScout` called the BC15 adapter directly after commit. A process crash or delayed worker could leave BC14 unable to distinguish delivery from lost acknowledgement.
- Decision proposed: keep outbox ownership and explicit SQL in the BC14 PostgreSQL adapter. A Scout-specific relay claims with `FOR UPDATE SKIP LOCKED`, commits a lease before network work, increments a monotonic fencing token, and conditionally records the result only for the current owner/token. Expired leases can be reclaimed. Retry timing is bounded exponential backoff plus injected jitter; PostgreSQL `clock_timestamp()` is authoritative for lease validity and retry scheduling. Delivery is at least once and uses the stable outbox event ID; receiver deduplication is required. Dead letters remain durable and require an explicit operator process.
- Alternatives: synchronous delivery in the application, a broker such as NATS, or a generic messaging framework. Synchronous delivery couples request completion to the receiver and has no reclaim protocol. NATS or a generic framework would add a dependency and operational surface without an approved cross-context contract or demonstrated throughput need.
- Consequences: a relay ACK means BC15 received the message. It says nothing about playbook approval or release. Fencing prevents stale updates in BC14 but cannot prevent duplicate external effects; only receiver idempotency can do that. The independent worker supports one-shot operation, idle polling and SIGINT/SIGTERM graceful stop. Production BC15 adapter, administrative redrive and production egress remain out of scope.
- Evidence: local PostgreSQL tests cover application return before delivery, the independent worker CLI, concurrent child-process claims, crashes after claim and after receiver commit, lease reclaim, stale fencing, bounded retry timing, lost acknowledgement with durable receiver deduplication, and dead-letter. Test receiver is not BC15 production.
- Human review required: lease/backoff limits, operator authorization, retention and redrive policy, receiver contract, and whether this relay remains adequate if throughput grows. This ADR remains Proposed until explicit approval.
